# AI Agent Protocols & Architectural Standards

This document is a MANDATORY guideline for any AI agent or developer working on the School module. Adherence to these patterns ensures system stability and consistency across the flattened database schema.

## 1. Database Schema Standards

- **Prefix**: All school tables MUST use the `sch_` prefix.
- **Domain Subdomains**:
    - `sch_ins_`: Infrastructure (Schools, Units)
    - `sch_acad_`: Academic (Years, Classes, Schedules)
    - `sch_hr_`: Human Resources (Staff, Leaves)
    - `sch_std_`: Students
    - `sch_log_`: Logistics (Assets, Inventory)
    - `sch_ops_`: Operations (Visitors, Graduation)
- **JSON Standard**: Always use `jsonb` for configuration/metadata columns.
- **Soft Deletes**: Always include `$table->softDeletes();` for master data and transactions.

## 2. Eloquent Model Standards

- **Unit Scoping**: School entities MUST use `Modules\School\Models\Traits\ScopedByUnit`.
- **SoftDeletes**: Models must use the `Illuminate\Database\Eloquent\SoftDeletes` trait if the table has `deleted_at`.
- **Foreign Keys**: Maintain strict naming consistency:
    - Use `staff_id` (not `teacher_id`, `employee_id`, or `counselor_id`).
    - Use `student_id`.
    - Use `school_unit_id`.
- **DocBlocks**: Always include `@property` hints for all columns to assist static analysis (PHPStan).

## 3. Validation & Testing

- **Pre-Commit**: Always run `npm run quality:backend` (PHPStan) and `npm run quality:frontend` (ESLint/TypeScript) before proposing changes.
- **Seeding**: New features MUST include a Seeder that generates at least one record for the current academic year (e.g., 2026) to prevent 404 errors in the UI.

## 4. Frontend Integration

- **Translations**: Use hierarchical keys in `Dashboard.vue` (e.g., `common.stats.students`) instead of flat strings.
- **Asset Sync**: After modifying frontend components, run `npm run build` and `npm run deploy:assets` to propagate changes to the backend public folder.

## 5. Multi-Unit & Scoping Rules

- **Model Isolation**: Every new model that belongs to a specific school unit MUST use the `Modules\School\Traits\ScopedByUnit` trait.
- **Global Data**: Data intended for the Foundation (Yayasan) or shared across units MUST have `school_unit_id = null`.
- **Media**: When uploading media, ensure it is assigned to the active `school_unit_id` unless it is explicitly marked `is_shared = true`.
- **Settings**: Use `Setting::get('key')` which is now unit-aware. Avoid direct database queries for settings that don't respect the unit scope.
- **Context Detection**: Always assume the unit context is handled by the `IdentifySchoolUnit` middleware. Do not hardcode unit IDs in URLs or logic.
